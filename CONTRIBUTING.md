# Contributing to API Tape

First off, thanks for taking the time to contribute! 🎉

The following is a set of guidelines for contributing to **API Tape**. These are mostly guidelines, not rules. Use your best judgment, and feel free to propose changes to this document in a pull request.

## How Can I Contribute?

### Reporting Bugs

This section guides you through submitting a bug report. Following these guidelines helps maintainers and the community understand your report, reproduce the behavior, and find related bugs.

- **Check for existing issues**: You might find that the bug has already been reported.
- **Use the Bug Report template**: When you open a new issue, please use the provided template to ensure we have all the info we need.

### Suggesting Enhancements

This section guides you through submitting an enhancement suggestion, including completely new features and minor improvements to existing functionality.

- **Use the Feature Request template**: This helps us understand the "why" and "how" of your proposal.
- **Provide context**: Explain why this enhancement would be useful to you and others.

### Pull Requests

- **Branch naming**: Use descriptive names like `fix/issue-id` or `feat/feature-name`.
- **Keep it focused**: One PR per fix or feature.
- **Test your changes**: Run `npm test` before submitting.
- **Update documentation**: If you're adding a feature or changing behavior, update the `README.md`.

## Style Guide

- Use TypeScript for all new code.
- Follow existing patterns in `src/index.ts` and `src/utils.ts`.
- Ensure your code passes linting (if applicable) and tests.

## Questions?

If you have questions about using API Tape or contributing to it, please open a [GitHub Discussion](https://github.com/laphilosophia/api-tape/discussions) or an issue with the `question` label.
